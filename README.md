# Keystroke Dynamics Authentication System

**Behavioral Biometric Authentication Using Machine Learning**

An end-to-end biometric authentication system that uses typing patterns to distinguish legitimate users from potential impostors.

Developed as a collaborative academic project for the Biometric Systems course at Sapienza University of Rome.

## Project Overview

Traditional authentication methods rely on passwords or physical biometric characteristics. This project explores **keystroke dynamics**, a behavioral biometric technique that identifies users through their typing rhythm.

The system combines keystroke data collection, feature engineering, machine learning, performance evaluation, and a web-based verification interface.

## How It Works

The authentication pipeline consists of five main stages:

1. **Data Collection:** A browser interface records key press and release timestamps while participants type a predefined phrase.
2. **Feature Extraction:** Raw keystrokes are transformed into numerical features describing typing behavior.
3. **Preprocessing:** Outliers are handled using the Interquartile Range (IQR) method, and features are standardized using StandardScaler.
4. **Model Training:** User-specific anomaly detection models learn patterns associated with legitimate users.
5. **Authentication and Evaluation:** The system compares new typing samples against learned patterns and evaluates its ability to distinguish genuine users from impostors.

## Machine Learning Models

### Isolation Forest

The primary authentication pipeline uses Isolation Forest to detect typing patterns that differ from an enrolled user's typical behavior.

### One-Class Support Vector Machine (SVM)

An alternative anomaly detection approach that learns a decision boundary around genuine-user typing patterns.

Both approaches are implemented using scikit-learn.

## Feature Engineering

The system extracts several categories of behavioral features:

- **Dwell time:** Duration for which a key is held down.
- **Flight time:** Time between consecutive keystrokes.
- **Digraph features:** Timing patterns associated with consecutive key pairs.
- **Typing speed:** Characters typed per second.
- **Statistical features:** Mean, standard deviation, median, minimum, maximum, and other measures.

These features form the numerical representation used for model training and authentication.

## Evaluation

The project includes implementations for evaluating authentication performance using:

- False Acceptance Rate (FAR)
- False Rejection Rate (FRR)
- Classification accuracy
- ROC curves and Area Under the Curve (AUC)
- Confusion matrices
- Separability analysis (d-prime)

Evaluation figures generated by the project are stored in the `img/` directory.

**Evaluation limitations:** The current evaluation includes genuine samples also used during training, so its reported performance should not be interpreted as an unbiased estimate on unseen users. In addition, the current implementation labels the average of FAR and FRR at a single operating point as EER; this is not a standard Equal Error Rate calculation and requires correction.

## Running the Project

Create a Python virtual environment and install the dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

The web interface additionally requires Flask and Flask-CORS, which are not yet included in the current requirements file:

```bash
python -m pip install flask flask-cors
```

With appropriately consented keystroke data placed in the expected `data/genuine/` and `data/impostors/` directories, run the training and evaluation pipeline:

```bash
python pipeline.py
```

To experiment with the local Flask interface:

```bash
python app.py
```

The web application is a research prototype and may require further configuration and testing. It is not intended for production deployment.

## Privacy and Limitations

Keystroke dynamics can reveal behavioral characteristics of individuals. Real participant data and associated trained biometric models should only be shared with appropriate permission.

The project demonstrates an experimental biometric authentication workflow, not a production-ready security system. Further improvements include independent test-set evaluation, correct EER computation, more robust verification, and privacy-preserving dataset handling.
